# Live JSArray element storage reached from the History forged view

**Status, October 20, 2026: location and reversible-write gates passed in two fresh 14.00 page sessions.** The forged History `Uint8Array` mapped a separately cloned 65,536-byte fixed buffer at index 131,064 in each session. After that buffer was detached, creating an 8,192-element JavaScript array placed its live element storage in the readable region. Changing element 0 from owned object A to B changed bytes at forged-view index 131,176. Changing element 1 changed bytes at 131,184, exactly eight bytes later. Both ordinary assignments restored. The operator reported no memory warning during the fresh-page repeat; the browser stayed responsive and connected.

This establishes a live JavaScript-value array slot reachable for read and reversible write from the forged view, with independent array identity and property oracles. The two words are strong candidates for JSCell addresses because they differ by `0x20`, have pointer-shaped upper bits, and substituting one changes the referenced object. The observation alone does not prove the precise JSValue encoding or an arbitrary-address read/write primitive. The tested write used only a valid word observed from another rooted object in the same process. It did not modify a native function, execute code, or cross the browser sandbox.
