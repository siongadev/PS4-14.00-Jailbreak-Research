# Address-calibrated object access on PS4 14.00

On October 20, 2026, the History forged `Uint8Array` reached both JSArray element storage and live ordinary-object properties. This page records the steps from measured view indexes to an address-directed write. All linked captures passed `python -m fw14lab.verify`; no absolute pointer from one page session was reused in another.

In session `6ada42a002854129b0ec5e447b83283d`, the retained forged view and JSArray slot exposed words `0x00000002010ac140` and `0x00000002010ac160` for two rooted objects. A signature scan found their live numeric properties at view indexes 2,867,528 and 2,867,560. Changing each property through ordinary JavaScript changed exactly its matching signature and restoring the property restored the bytes. The 32-byte index spacing matched the 32-byte difference between the two observed words. [Verified signature capture `899a70132d0b4df598823a58f727cf1b`](../captures/899a70132d0b4df598823a58f727cf1b.json), SHA-256 `b2d634e223a16dae9fc0b10e1f1d1960946d14b6618d140da8d66ce52be5d256`.

An initial direct-write command stopped before writing because the old signature had acquired two copies in the scan region. Its [verified capture `bef05e7e9bb54aca997e1fd190e2ca98`](../captures/bef05e7e9bb54aca997e1fd190e2ca98.json), SHA-256 `cbc2b214b2c90e419ec5e5d21dfc62b7e3caee11013607ff0cc5a5bfdb4d4c8c`, records the gate error. The revised command first changes the rooted object's property through normal JavaScript to identify which of the candidate byte signatures is live. It then writes four bytes **through the forged view** at only that location. The object's JavaScript property changed to the chosen value; a second object's property stayed unchanged; restoring the original four bytes restored the first property's value. [Verified capture `2b6f65714d2b4c80bac74141f3aa2290`](../captures/2b6f65714d2b4c80bac74141f3aa2290.json), SHA-256 `409a501281e4338d965af0d03bcaa6b963bfab0e3e228340a4c9d61de84f9cf5`.

The direct write repeated on a new page session `44f9147623634890af655a9eaf17cd88`. The first storage setup missed the target allocation without detaching it; the second mapped the 65,536-byte fixed buffer and found the two JSArray slots at 131,176 and 131,184. The signature probe located two new object words `0x00000002010ac260` and `0x00000002010ac280` at indexes 2,867,816 and 2,867,848. The direct view write again changed only the selected object's property and restored it. [Storage setup `62763750d7d944f4902dca361b9ea940`](../captures/62763750d7d944f4902dca361b9ea940.json), SHA-256 `206f8603e68160fb1260613dbdf3fe31a85f1b5a2eb8d5bb00ecdf06df5274ce`; [signature `e799d2f8cea143b2918e3f20ade341b5`](../captures/e799d2f8cea143b2918e3f20ade341b5.json), SHA-256 `008cf4d34b6d00aa10308f93da1e178e22a261e4a049f26e6ea17dbd2fe2a7ab`; [view write `86f8441505d2483b8bb14c15d61c767c`](../captures/86f8441505d2483b8bb14c15d61c767c.json), SHA-256 `4433f73fa9c3ae9cbd5fb8e5dcca8cce7db179ceba3822cf2740d1dd5dcd7061`.

In that second page, a separate probe built a new anchor object, located its live marker at index 2,868,552, and read its JSArray word `0x00000002010ac540`. The formula `word + 8 - index` gave a page-aligned view base of `0x200df0000`. After creating and rooting 256 spacer objects, the probe read a newly created target object's word `0x00000002010ae580`. Without scanning for the target marker, it predicted the marker's view index as `word + 8 - base = 2,876,808`. The old value was present there; normal property mutation changed those bytes; and a forged-view write changed the target's JavaScript property while the anchor stayed unchanged. The target bytes and property were restored. [Verified address-directed capture `df53167a36b74eb5999ebe25bf46c9cd`](../captures/df53167a36b74eb5999ebe25bf46c9cd.json), SHA-256 `acc3e5d9afba07f40de4dfa091c6cbcdbead52a4feea386c0355108d778315f1`.

The address-directed command then passed on another fresh page session, `fbf667f51e13484d99f9b55a4df988a8`. Its first storage setup missed the fixed-buffer allocation and wrote nothing; its second setup paired the live JSArray slots. A new anchor word `0x00000002010ac360` and property index 2,868,072 again yielded base `0x200df0000`. After 256 spacer objects, a new target word `0x00000002010ae3c0` predicted index 2,876,360. Its property mutation and view write both worked at that calculated index; the anchor remained unchanged and target bytes restored. [Verified setup `1b2496208d5d41428bc1858a2a03c791`](../captures/1b2496208d5d41428bc1858a2a03c791.json), SHA-256 `19ea64b873b3560b77869d752dd4dd9ba445e22089eb79b7d6219bbe53a6c23c`; [verified address-directed repeat `abbc6a98dfa74b54b10109718b2c25ec`](../captures/abbc6a98dfa74b54b10109718b2c25ec.json), SHA-256 `926094595ae06439c41f2a5d0afc8646414952c53820ffd43b0e2dafb07eb3c8`.

The same page used the calibrated base to read 64 bytes at the observed words for two newly created JavaScript functions, `0x0000000201019c60` and `0x0000000201019ca0`, at view indexes 2,268,256 and 2,268,320. Both functions returned their expected values afterward, and the JSArray leak slot was restored. [Verified function-cell read `63b5e48787a243caa9a5bfc4c616f1a8`](../captures/63b5e48787a243caa9a5bfc4c616f1a8.json), SHA-256 `dd476bcb5197e79781cc72433a9d66d9b2e834064368878543ff7214f92fbf15`. This is a read-only layout observation; none of the function bytes was modified.

A third fresh page, `ec8316ce7e2b4c268ed6dd3c1abe7f40`, mapped its JSArray slot at index 155,752 instead of 131,176. The same address-directed probe recalibrated a **different** page-aligned base, `0x200e34000`, from anchor word `0x00000002010ac340` and marker index 2,589,512. It predicted and reversibly wrote a later object's property at index 2,597,736. [Verified capture `490124d4d33048e48086d72a67882964`](../captures/490124d4d33048e48086d72a67882964.json), SHA-256 `42a903010c0bd591995b8fc45287e6191b9275cf60fbdb86be30f7da58c830c2`. This confirms the probe must calculate the base anew for each page; the earlier `0x200df0000` value is not a reusable process address.

The `+8` offset and calculated base are directly supported for this observed one-property object shape: two fresh sessions predicted a separate target property without searching for its signature and then read, wrote, and restored it at the calculated index. The current result establishes address-directed access to measured live JavaScript objects and read access to newly created function cells in the view's reachable region. It does not establish that every process address is mapped or safely accessible through the view, nor does it show control of a function's executable entry. The operator reported no memory warning on either fresh-page address-directed run.
