# Current-process read and gadget validation on PS4 14.00

The History forged view now reaches a live `Uint8Array` cell. Two separately owned 65,536-byte typed arrays had distinct cell words and data pointers exactly 65,536 bytes apart. Replacing one cell's observed data-pointer word with the other's made ordinary indexed reads of the first array return the second array's bytes; restoring the word restored its own bytes. [Verified pointer-swap capture](../captures/0f1aa086a7634329be030e271d5f3b7d.json), SHA-256 `52ab36d7430573066a4128c8fb287f29be22139fa34bd6892876cde7e6cac622`. This turns the measured cell write into a pointer-directed read/write through a normal typed array. The substitution was confined to rooted, owned arrays during that check.

Using the same temporary pointer swap, the console read 64 bytes at a pointer found in the live `Math.expm1` function cell, below the forged view's original base. Its offset `+40` contained a code pointer, `0x841172880`. The candidate WebKit base from that pointer and a historically 14.00-checked relative location was `0x83ebec000`; the base is process-specific. [Verified metadata capture](../captures/fd78895aa8bf4013b7a431ae5acb21d2.json), SHA-256 `d2dedb0f04435941c81dc7341ffadd0bf3e97ad98446309567fe110054771a3e`.

A current-process read of three candidate gadget locations matched their expected instruction bytes and restored the typed-array pointer. [Verified first gadget capture](../captures/09756ea8ade548cf9c7228cfc51200a2.json), SHA-256 `dc231a36601bc1b3cee7575aba703acd3d4e9c33dc9e89071f6cdb624008d371`. A second probe read all 15 historically 14.00-checked locations twice, found stable bytes at every location, and matched all 15. [Verified full gadget capture](../captures/dd65edb9599b4de9a55e60e7fa14d182.json), SHA-256 `a363323b103f1b6222894f0266e1d045a699fbe51e49ed792fd94b6a6fdca954`.

The next preflight used two import entries in that same WebKit image. Both pointed to current-process code with the expected prologues, and two number-specific wrappers read at offsets from the first live import matched stable bytes. The number-20 wrapper was `48c7c0140000004989ca0f057201c348`. [Verified import-wrapper capture](../captures/58603d96a0a5418196226518efca8fe5.json), SHA-256 `748d858e487be226d1af687badc27ba7410fea97127961749cc5cc299322250c`. The old project's symbol names and module-base offsets were not needed for this result; the current process supplied the import pointers and code bytes.

The typed-array pointer and WebKit addresses are recalculated for each page. A 16 MiB contiguous forged-view scan on a later fresh page ended in a system-memory warning before a result and must not be used as a calibration shortcut.
