The operator had reported no warning from the preceding JSArray repeat. These checks sought an independently measurable relationship between an absolute native pointer and the forged History view's index zero; none was found.

The last result is a negative result for that window and filter, not proof that the process has no pointers to these buffers. Most of the measured region was filled backing-store data. The previous 65,536-byte freed-slot sample also retained its `0x91` bytes rather than exposing a link. Repeating the same scan without a reason to expect pointer-bearing storage would add little. The next calibration attempt needs a measured allocation whose contents include a pointer to another measured allocation, or an independent way to read the internal pointer of one leaked JavaScript object. A pointer-shaped word alone remains insufficient: a candidate view base must predict a second live region and support a reversible read/write oracle before it is used to inspect function cells or gadget bytes.

A separate fresh page session `758dc3e41be54789b718d84e56d38940` then passed the usual JSArray-storage setup in [verified capture `c74dd8d91c2d4e50be9fa683bacbbf60`](../captures/c74dd8d91c2d4e50be9fa683bacbbf60.json), SHA-256 `f5e462e3bc35307e15130229761f9fb44f6a1721192c2cb18520437038d3e25a`. The follow-up `clone_history_object_inline_scan_v1` leaked distinct array-slot words `0x00000002010ac620` and `0x00000002010ac640` for two new rooted objects with the same numeric `marker` property. Changing each marker from `0x41414141` to `0x42424242` produced **zero changed bytes** in the first 524,288 forged-view bytes; both properties and the array slot restored. Its [verified capture is `d79a030bb53e44ce9ebee69a8e9caafc`](../captures/d79a030bb53e44ce9ebee69a8e9caafc.json), SHA-256 `e520aadff6bd8c8799bd79332cbd7e73844e2e61bda7a3689cda0394def56e87`. This excludes a direct property-differential calibration in that tested window. It does not show whether the object cells lie before the view base, farther forward, or in a separate mapped region.

The same page's [verified capability capture `53c5a039875a4432b405decd812b15b2`](../captures/53c5a039875a4432b405decd812b15b2.json), SHA-256 `0c0df4b9a8e0798edff9ac452bc63a07758893837cff37d343960b6b73498540`, reports `WeakRef` and `FinalizationRegistry` as functions, but no exposed `gc`, `GCController`, or `internals`. A garbage-collection-dependent freed-butterfly metadata test therefore has no direct completion trigger on this browser and was not sent.

The operator reported no memory warning from the calibration and object-location checks, and the page remained responsive and connected.

## Later result

A 2 MiB property differential still found no object bytes in the tested range: [verified capture `c3dea2a4b3314b4b86cc151ba9002fb5`](../captures/c3dea2a4b3314b4b86cc151ba9002fb5.json), SHA-256 `54ac71e4d29b1a0d26ba7084dd97f1037ad535ca0b565ee8a701abf69f637513`. A 4 MiB whole-range differential observed thousands of unrelated changing bytes, so the simple before/after comparison was too noisy: [verified capture `c738bd618b564200afe1a1d20839d54a`](../captures/c738bd618b564200afe1a1d20839d54a.json), SHA-256 `089a9c6e90799d62d16bc201af355d38b02e8a41d4630a8fdf9b756a7b8cef7b`. That positive result supersedes the earlier address-calibration gap; the negative scans above remain useful limits of their particular windows and filters.
