# Owned-buffer native call through the History primitive on PS4 14.00

The current project independently reached browser-process code-reuse execution on the Settings-confirmed 14.00 console, then repeated it on a fresh browser page. A probe constructed four owned 65,536-byte typed-array backings for a pivot, store, stack, and output frame. It obtained their current-process data addresses from live typed-array cells and compared the planned bytes through an independent pointer-directed read. The 15 WebKit gadget signatures, two import targets, number-20 wrapper, callable slot, and pivot-object cell were checked in the same browser session. [Verified first call-plan capture](../captures/13018deba56248f1af286eef44478f89.json), SHA-256 `90aafa06a673d49ee218e82fe4638de2908c88e9afd729ec559238633a898ac2`.

The separate execution probe rechecked the live object identities, function slot, code bytes, owned chain bytes, zeroed output frame, and normal `Math.expm1(1)` result. It then temporarily changed the native callable's entry pointer and the pivot object's first word, invoked the call once, and restored both pointers in a `finally` block. The call returned; the formerly zeroed frame held decimal `140` with zero high word. The capture reports restoration of the callable slot, pivot cell, typed-array data pointer, and ordinary `Math.expm1` behavior. [Verified first native-call capture](../captures/4b68be7f214a443abd15321e907d4977.json), SHA-256 `a976e13db0c398c827892f64c4348ea2b4727c94b11ef08fb0e2e1375dacb9b8`. The operator saw no memory warning and reported that the page remained responsive.

After a page refresh, the independent JSArray and pointer-swap setup passed again. The new forged-view base was `0x200ff0000` rather than `0x200e34000`; the WebKit base was `0x80b2b4000` rather than `0x83ebec000`. This page's native executable metadata was found through a different live function-cell field, selected by its aligned code pointer and matching gadget bytes. The rebuilt plan checked all 15 gadget signatures and its own buffers. [Verified second call-plan capture](../captures/149cff77c006431091fc58e652bbbe42.json), SHA-256 `a7ed451d30d2eb6004d37961173278344f3b6de920af3f67ca3541827715636c`.

The fresh-page execution returned decimal `141` in a frame that had again started at zero. It reported a normal return, zero high word, and restoration of the function slot, pivot cell, typed-array pointer, and ordinary `Math.expm1` behavior. [Verified repeat capture](../captures/242d169c7e3942c8997b675f793ded1b.json), SHA-256 `7ec4dee57b84f4a79ec00047ede49a2e6341ff057f40dd3417583ba14d6aeb77`. The operator again confirmed a responsive, connected page and no memory warning. The different addresses show that the repeat recalibrated its own page state; a refresh alone does not prove a new browser process.

This result executes a short chain through the browser's existing native code and a live number-20 wrapper. It is not injected machine code, a sandbox escape, or kernel execution. The numeric return is consistent with a process identifier, but the milestone rests on the controlled native call, changed owned output frame, and restoration gates rather than that label alone.

During the repeat, one broad 16 MiB forged-view scan caused a memory warning before producing a capture. A new page used a bounded 0–2 MiB anchor check, a rooted object batch, and a separately validated typed-array pair to regain calibration. The working probes never reuse a previous page's absolute addresses. This scan failure is recorded as a limit of the calibration method, separate from the two successful calls.
