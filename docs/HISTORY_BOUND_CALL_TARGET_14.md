# Bound built-in call-target redirection on PS4 14.00

On October 20, 2026, the calibrated History forged view read the cell of a newly created function bound to `Math.expm1`. At offset 24, its eight-byte word exactly matched the live JSArray word leaked for `Math.expm1`. A separate function bound to `Math.log1p` had the same field equal to the live `Math.log1p` word. These observations and normal calls passed in [verified callable-layout capture `88eed8a84fd140b9ad144ca99739def2`](../captures/88eed8a84fd140b9ad144ca99739def2.json), SHA-256 `cc4e02dbdf838e80d5a844be8c2ebe31c5d304f64fa070850404978193ceedfe`.

A follow-up probe verified both field/word relationships again, read the original eight bytes, and wrote **only the observed `Math.log1p` word** into the bound `Math.expm1` object's field through the forged view. Calling the same bound function with argument 1 returned `0.6931471805599453` during the write, matching `Math.log1p(1)` instead of its baseline `1.718281828459045`. The independent bound `Math.log1p` control and direct `Math.expm1` remained unchanged. The probe restored all eight original bytes in a `finally` block and the original bound call again returned `1.718281828459045`. [Verified target-swap capture `f20235a9b3914651a87fd0342c68158c`](../captures/f20235a9b3914651a87fd0342c68158c.json), SHA-256 `f07d758af2aea6a594283b846a48a07e06ea753f8003277fda1363d72e14b507`. The view base was freshly recalculated as `0x200df0000` on that page.

The same source passed on a fresh page session `ec8316ce7e2b4c268ed6dd3c1abe7f40`, which independently calibrated a **different** view base, `0x200e34000`. Its bound `Math.expm1` cell was at `0x000000020112c618`; the original target word was `0x0000000201019700` and the substituted `Math.log1p` word was `0x0000000201019a00`. The bound call again returned `1.718281828459045 → 0.6931471805599453 → 1.718281828459045`, while the independent functions remained normal and all eight target bytes restored. [Verified setup `df3b845e39d6415d9c49fabcdd54fbe3`](../captures/df3b845e39d6415d9c49fabcdd54fbe3.json); [verified address calibration `490124d4d33048e48086d72a67882964`](../captures/490124d4d33048e48086d72a67882964.json), SHA-256 `42a903010c0bd591995b8fc45287e6191b9275cf60fbdb86be30f7da58c830c2`; [verified callable layout `8035f57b827849fa985d66fa7bd2fe43`](../captures/8035f57b827849fa985d66fa7bd2fe43.json), SHA-256 `fd9a19cf6f5f1752dcf92bb9302c4d5597452d3bbf097ba19367`; [verified target swap `aff8dc8ce5374e009a66c366690d5b05`](../captures/aff8dc8ce5374e009a66c366690d5b05.json), SHA-256 `317ad8c6f0e2f0829a192068ef634527f667893d583b50b49022df5db5bec089`.

This is fresh-page repeated 14.00 evidence that an eight-byte field of a bound function controls which existing built-in target it calls. The probe substituted two valid, rooted function-object words observed in the same process; it did not forge a code pointer, locate a WebKit module base, or execute an arbitrary native address. Read-only captures of both built-in cells were also saved: [`2b9d0773460245dc9d6a30f5d0e6c717`](../captures/2b9d0773460245dc9d6a30f5d0e6c717.json) and [`3a4d3ec5b8f0413dbbd47f564e414c41`](../captures/3a4d3ec5b8f0413dbbd47f564e414c41.json). Their directly visible fields were process pointers and encoded words; no live WebKit code pointer has yet been independently identified. The next step is to obtain such an anchor before rechecking any historical gadget locations.
