# Unix descriptor-passing error path on firmware 14.00

Executed 2026-10-25 on a freshly prepared firmware 14.00 browser page, session `7fb73a26790344ee9f3e08deef70e32e`, WebProcess PID 64.

[FreeBSD-SA-26:57.unix](https://lists.freebsd.org/archives/freebsd-security/2026-August/000557.html) describes a `SOCK_STREAM` Unix socket receive-path use-after-free when processing `SCM_RIGHTS` fails. The [official fix and regression test](https://github.com/freebsd/freebsd-src/commit/06833c3e9813) use a low soft `RLIMIT_NOFILE` to force an `unp_externalize()` error with queued data behind the rights-bearing message. The advisory affects upstream FreeBSD 15.0 and later. Sony 14.00 kernel equivalence is unknown.

The [v60 native installer](../probes/clone_history_native_invoke_install_v60.js) passed, verifying and publishing wrappers 27 (`recvmsg`), 28 (`sendmsg`), and 195 (`setrlimit`) alongside 194 (`getrlimit`) and socket wrappers. The [rights roundtrip](../captures/c17be7058b514cf8bb651ba65cef02c5.json) passed with a 16-byte payload, `cmsg_len=20`, `msg_controllen=24`, level 65535, type 1, and received fd 11. This validates the live `SCM_RIGHTS` message layout.

The first [error-path attempt](../captures/6ee5024080b4409489c7be6953d4661f.json) lowered the soft fd limit to one but failed to restore its prior value; the result preserved no receive details. A [recovery call](../captures/c59013a9730141b48feea918cb9a4f6d.json) measured soft 1, hard 12,556 and successfully raised soft to 1,024. The original soft value was not captured. Later probes restore to 1,024; [post-stress readback](../captures/ca8926d77b564f9a9b843f636dc8c822.json) confirms soft 1,024, hard 12,556. The page remains responsive.

With the corrected restore, low-limit `recvmsg` returned `-1` and errno **40 (`EMSGSIZE`)** in both [nonblocking](../captures/4881779256c74fd8865207fe6609ce71.json) and [ordinary](../captures/b8d3a26899a24b29827cf3c1ccbb4f48.json) modes. This differs from upstream FreeBSD's regression test, which expects `EMFILE`. After raising the limit, the first 16 bytes were recovered. The [full 2 KiB case](../captures/17c2549bcfed4812839412a23b760daa.json) also recovered every trailing byte. The first [64-attempt burst](../captures/ea3c15b9b8384b96b611a5fd7dbc4064.json) passed. Together with sixteen further batches, it produced **1,088 complete 2 KiB attempts**, each with errno 40, exact payload recovery, intact guards, and cleanup.

The [v61 installer](../probes/clone_history_native_invoke_install_v61.js) added byte-checked socket-option wrappers. A [socket-buffer measurement](../captures/0d4e08525fff43e79aa4736449a313fd.json) found default send/receive buffers of 8 KiB and successfully enlarged a fresh socket's receive buffer to 16 KiB. The [larger case](../captures/34572f48cd6e4b41bac5421a4609b9ed.json) set both owned socket buffers to 16 KiB and queued 9,830 bytes behind the rights-bearing message, about 60% of the receive buffer. It recovered all bytes after the errno-40 failure. Eight 64-attempt batches yielded **512 complete larger cases**, all with the same result; the first [burst capture](../captures/cc4aea7d002549ce935579e66c09e5d0.json) and the last [burst capture](../captures/86bfddd7b34a4d93a55ed0b042a17486.json) bracket them. All 31 stored rights-path captures on this page passed `fw14lab.verify`.

The input exercised live descriptor passing, forced an error while rights and data were queued, and checked recovery under two buffer sizes. No measured corruption, authority change, or kernel memory primitive emerged. The different error code and intact stream do not establish Sony's implementation of the upstream FreeBSD 15 bug; further repeats of the same input have low value.
