# Firmware 14.00 History primitive: controlled fixed-buffer slot reuse

The [forged view](HISTORY_NATIVE_OOB_14.md) can observe a freed fixed-buffer slot after the owning buffer is detached. First, the probe dynamically locates a 65,536-byte alias to a live cloned fixed `ArrayBuffer` by comparing every byte of a 262,144-byte region before and after filling that buffer. It then calls `structuredClone(0, { transfer: [buffer] })`: the buffer is in the transfer list but is absent from the returned value. The old normal view reports length zero. The probe allocates 32 fresh 65,536-byte fixed buffers, each with a distinct marker. The **first** new buffer's marker appears at the old slot through the forged view; a normal write to the new buffer's first byte is visible through the forged view and is restored.

The verified 14.00 [capture `5dfc2c4467424374b37aa8529b2d239b`](../captures/5dfc2c4467424374b37aa8529b2d239b.json), SHA-256 `135f441dedc9146a5348df9f947a83dbaf87650477e030c81021ebc77bf5347a`, records: old alias index 155,640; old marker `0x91`; detached old view length zero; new marker `0x20` in eight consecutive forged-view bytes; matched spray index zero; normal write changed forged byte to `0xD7`; restoration returned it to `0x20`. The input-side fixed buffer and the forged view's resizable backing buffer kept their canaries. `python -m fw14lab.verify` passed.

The corrected source's fresh-page repeat, [capture `8666163393f44260b920865e14cae968`](../captures/8666163393f44260b920865e14cae968.json), SHA-256 `2f228a316227576e33f0db32aee10a1f5149f2b01a7733d41abbd8ece0e0820f`, again found marker `0x20` at index 155,640, observed the normal write as `0xD7`, and restored it to `0x20`. Its source SHA-256 is `1ec7d6c5a428a608cb7be293c4ebf27f329dabbf07c81cee69735fb131e3f3b3`. An initial fresh-page attempt with the earlier source stopped at the 262,144-byte scan boundary after counting only the first 20,488 bytes of the same 65,536-byte allocation; the corrected source follows that identified allocation through its end.

An earlier run of the same experiment, [`e257f23f013f4ed9a5426adddd20801c`](../captures/e257f23f013f4ed9a5426adddd20801c.json), reached the alias-check branch, but a ninth progress marker exceeded the collector's eight-marker limit. It is an instrumentation error, not a measurement of the final bytes. The corrected source removed one marker and produced the capture above.

This is controlled reuse of **attacker-created fixed-buffer backing memory**, reached from a view attached to a separate resizable buffer. Subsequent work placed a live native pointer vector in the slot; see [native pointer result](HISTORY_NATIVE_POINTER_RW_14.md). Neither result yet establishes arbitrary process read/write or code execution.
